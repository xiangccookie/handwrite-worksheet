## 二 · 你说的“透视不对”，确实是真问题

我一开始只把文字**绝对水平**排上去。但照片里的纸不是平的：**横线左右不等高，而且倾斜量从上到下还在变**。
字是水平的、线是斜的，两者不在一个平面上 —— 所以看着像贴上去的。

现在的做法：把文字先排在**平整的纸面坐标系**里，再用**单应变换（homography）**整块投到照片的透视平面上。
文字于是继承了纸张自己的倾斜与会聚。

### 实测出来的纸面几何（不是估计）

| 测量项 | 数值 | 怎么测的 |
| --- | --- | --- |
| 横线格距 | **19 px** | 横线响应图沿 x 平均后做自相关 |
| 顶部倾斜 | **+6.87 px / 913 px**（右端更低，约 +0.43°） | 分区互相关 |
| 底部倾斜 | **+24.25 px / 913 px**（约 +1.52°） | 分区互相关 |
| 自相关峰值 | 0.493 | 见 `_auto_pitch()` |

“顶部 6.87、底部 24.25”说明横线是**扇开的**（在会聚），这正是需要透视变换的原因——
纯旋转只能把整张纸转一个角度，做不出“越往下越斜”。

### 三个把我坑到的技术点（留作记录，改脚本前先看）

1. **左右配对会给出反号。** 一开始我在左右两条竖带上各自找横线，再按序号配对。
   两侧检出的线数不同（77 vs 80），配对错开一根，高度差就假性偏移整整一个格距，
   于是算出“右端更高”，和真相**方向相反**。现在改成不依赖配对的互相关。
2. **格距交给优化器会被锁到错值。** 让优化器自由搜格距，它收敛到 24.65 px（真实 19）。
   格距一错，倾斜就跟着偏。现在格距先用自相关定死，再谈别的。
3. **“倾斜 vs 高度”不是直线。** 线性拟合在顶部只给出 +4.05 px，而实测是 +7.1 px。
   曲线是“先平后陡”，所以改成二次拟合，拟合最大偏差降到 1.93 px。

另外，**估计量本身必须先过基准测试**：我先造了一张已知倾斜 +0.010 的合成纸，
确认互相关和拟合都能正确还原符号，再拿它们去量真照片。否则无从判断谁对。

## 三 · 怎么换成你的文字

### 方式 A（推荐）：把文字发我
贴文字 + 说一句“隔行/一格一行”，我改一行就出图。

### 方式 B：自己跑（在 `C:\Users\Administrator\Desktop\DeepSeek\闲聊` 目录下）

```powershell
python photo_handwrite.py --photo 纸张背景_原始.jpg --text "见字如面。" --rows-per-line 2 --out 我的.png
```

逐段讲清：

- `python photo_handwrite.py` —— 启动主脚本。它会自动去同目录找 `handwrite.py`，**两个文件必须放一起**。
- `--photo 纸张背景_原始.jpg` —— 底板照片。换别的纸照片也能用，脚本会自动找纸面、自动量透视。
- `--text "..."` —— 要写的文字，换行写 `\n`。
- `--rows-per-line 2` —— **每个文字行跨几根横线**。`1` = 每根线写一行（字最小、最贴格）；`2` = 隔一行写（默认、好读）。
- `--out 我的.png` —— 输出路径。

**预期输出**：打印一行字典，含 `size_px`、`row_pitch`、`perspective: true`、`tilt_top_deg`、`tilt_bot_deg`。
**检查点**：✅ `perspective: true` 且 `tilt_bot_deg > tilt_top_deg`（说明会聚方向对）；
❌ 出现 `[警告] 横线模型拟合失败` → 退回无透视，多半是纸面区域检测不准，可用 `--box` 手工指定。

## 四 · 参数表

| 参数 | 作用 | 调大 | 调小 | 建议 |
| --- | --- | --- | --- | --- |
| `--rows-per-line` | 每个文字行跨几根横线 | 字更大、更疏、更会跨线 | 更贴格子 | 2 |
| `--size` | 字号（像素） | 字更大 | 更小 | 不写则自动＝行距×0.78 |
| `--pitch` | 行距（像素） | 行更疏 | 更挤 | 不写则＝跨线数×格距（会被吸附成整数倍） |
| `--ink` | 墨色 `R,G,B` | 越浅越发灰 | 越黑 | `22,26,42`（蓝黑钢笔） |
| `--left-pad` / `--right-pad` | 左右留白（像素） | 更靠里 | 更靠边 | 48 / 40 |
| `--top` | 首行基线在左端的 y | 整块下移 | 上移 | 不写则自动 |
| `--wobble` | 手抖强度，0 = 像打印 | 更潦草 | 更工整 | 0.9 |
| `--seed` | 随机种子 | — | — | 7 |
| `--box` | 手工指定纸面 `x0,x1,y0,y1` | — | — | 自动检测不准时才用 |
| `--no-persp` | 关闭透视校正 | — | — | 一般不要用 |

## 五 · 墨迹为什么看着“长在纸上”

不是把字贴上去，而是**正片叠底**（multiply，图像处理里的一种混合方式）：墨色会乘上纸张自身的明暗。

- 效果一：字落在那道折痕的阴影里会自动变暗，落在亮处显得清透。
- 效果二：字不会像贴纸那样在暗处还亮着一块。
- 如果改用普通覆盖（直接把墨色写上去），阴影区域的字会亮出来，一眼看出是 P 的。

另外用照片自身的高频细节（纸面颗粒）调制墨量（±16%），让墨看起来是**渗进纸纹**里的。

## 六 · 手写引擎：内置抖动 vs handright（重要）

最初是自己写的“逐字扰动”，后来发现那个 **HandWrite 的 Windows 包只是个 PyQt5 图形外壳**，
它 `core.py` 第 4 行是 `from handright import Template, handwrite` —— 真正干活的是 PyPI 上的
**`handright`** 库（BSD-3 许可、纯 Python、wheel 只有 12 KB）。

所以本脚本现在支持两个引擎：

| 引擎 | 原理 | 优点 | 缺点 |
| --- | --- | --- | --- |
| `handwrite`（内置） | 逐**字**随机：整字平移 / 旋转 / 缩放 / 墨色深浅 | 快（1.3 秒）、零额外依赖 | 放大看是“每个字整体歪一点”，笔画本身笔直 |
| `handright` | 逐**笔画**随机：笔画左右上下抖、笔画轻微旋转，另有行距/字号/字距扰动 | 放大看笔画在颤，明显更像手写 | 需 `pip install --no-deps handright`（Pillow 12 已实测兼容） |

安装命令（本机已经装好）：
```powershell
python -m pip install --no-deps -i https://pypi.tuna.tsinghua.edu.cn/simple handright==8.2.0
```
- `--no-deps` 是关键：handright 声明 `pillow<11`，而本机是 12.3.0。
  带上 `--no-deps` 就不会去动 Pillow 版本，实测 8.2.0 在 Pillow 12.3.0 下正常工作。
- 换引擎：`--engine auto|handright|handwrite`（默认 `auto`＝装了 handright 就用它）。

**扰动强度**用 `--wobble` 控制（默认 0.9，它会等比缩放 handright 的各项 sigma）：

| wobble | 观感 |
| --- | --- |
| 0.55 | 工整但仍有生气，**最像正常人写的** |
| 0.9 | 默认，笔画颤动明显 |
| 1.2 | 潦草、像赶时间写的 |

> 注意：那个 HandWrite 仓库**没有声明任何开源许可证**（GitHub API 显示 `license: None`），
> 属于“保留所有权利”。所以我们**没有下载它的 82 MB 可执行包**，而是直接用了它依赖的、
> 许可证清晰的 `handright` 库。想用它的图形界面可以自己下载，但脚本用不上。

## 七 · 已知限制

1. **做不到“每条基线严格落在横线上”。** 我试过：把行距吸附成格距整数倍、把基线对到格子上，
   实测基线与最近真实横线的偏差最大仍达 **14.89 px**。原因是这页纸的格距并不均匀（页面有弧度）。
   要精确贴线必须**逐条追踪横线**——你说过不做，所以现在只保证“透视一致 + 字号与格距相称”。
2. **纸面弯曲无法用单应变换表达。** 纸张不是刚性平面（尤其左边缘靠近装订处是卷的），
   变换只能做到“一个平面”的程度；越靠装订缝，误差越大。
3. **字是水平排布后整体投影的**，所以每行内部的行距严格相等；真实手写会有细微不等。
4. **只支持横排**，竖排没做。
5. **字体是楷体 + 逐字扰动**，不是真手写；放大看同一个字结构完全一样，只是歪的角度不同。
   装开源手写体（如霞鹜文楷）后用 `--font` 指定路径会明显更像。
6. **分辨率**：1080×2400 是手机屏幕级。发朋友圈、做配图够用；要打印（300 dpi）得用手机原图重拍/提供。
